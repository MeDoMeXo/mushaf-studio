# ٠٩ · المعايير العالمية، الأمان، الاختبارات، والنشر

تم فحص المشروع ومطابقته لمعايير الويب العالمية ومهارات التطوير القياسية (`vercel-labs/agent-skills` لـ React/Next.js وWeb Design Guidelines، وWCAG 2.2 AA، ومعايير SEO/Schema.org).

---

## ١. قائمة التحقق من المعايير العالمية المطبّقة

### أ) الأداء والخطوط (Zero-CLS & Next.js Best Practices)
- استبدال روابط Google Fonts الخارجية بتحميل ذاتي محسّن عبر `next/font/google` لجميع الخطوط العربية الستة مع `display: 'swap'`.
- ربط الخطوط بمتغيرات CSS و`resolveCanvasFontFamily()` لتفادي أي تراجع في خط الرسم على `<canvas>`.
- خلو المشروع تماماً من أخطاء وتحذيرات ESLint (**0 Errors · 0 Warnings**).
- معالجة دقيقة للـ React Hooks (تحديث الحالة الوظيفي داخل `useEffect` لتفادي التبعيات غير المستقرة وإعادة التصيير غير الضرورية).
- **سقف ٦٠٠ سطراً لكل ملف مصدر** (`.ts`/`.tsx`): يُطبّقه `scripts/check-file-size.ts` كخطوة CI إلزامية قبل الـ lint على كل push/PR؛ الملفات الضخمة فُكّكت إلى وحدات (أقسام مكونات، hooks مخصصة، وحدات lib مع براميل إعادة تصدير تحفظ مسارات الاستيراد الأصلية) — حالياً كل الـ ١١٠ ملفات ضمن السقف.

### ب) إمكانية الوصول (WCAG 2.2 AA)
- لغة عربية واتجاه صريح (`<html lang="ar" dir="rtl">`).
- رابط تخطٍّ مباشر للوحة المفاتيح وقارئات الشاشة: `تخطّ إلى المحتوى الرئيسي` يقفز إلى `#main-content`.
- تعيين `aria-current="page"` للروابط النشطة في شريط التنقل (سطح المكتب والجوال).
- تعيين `color-scheme: light` و `color-scheme: dark` لضمان تناسق عناصر المتصفح الأصلية (أشرطة التمرير ومنتقيات الإدخال).
- إبراز واضح للتركيز بلوحة المفاتيح (`:focus-visible` بإطار ذهبي `2px solid var(--brand-gold)`).
- احترام تفضيل تقليل الحركة (`@media (prefers-reduced-motion: reduce)`).
- نوافذ حوارية (`role="dialog" aria-modal="true"`) تدعم الإغلاق بزر `Escape` والنقر خارج الإطار، وأزرار حالة تستخدم `aria-pressed` و `aria-selected` و `role="switch"`.

### ج) تحسين محركات البحث والـ PWA (`app/layout.tsx`, `app/manifest.ts`, `app/robots.ts`)
- بيانات وصفية كاملة (`metadata`: العنوان، الوصف، الكلمات المفتاحية، OpenGraph بالعربية `ar_SA`، بطاقة Twitter `summary_large_image`).
- تصدير `viewport` قياسي مع `themeColor` للوضعين الفاتح (`#F7F4EC`) والداكن (`#0A1513`).
- تضمين بيانات منظّمة **Schema.org (`WebApplication` JSON-LD)** باللغة العربية تصف المزايا الأساسية للتطبيق.
- مسار `/manifest.webmanifest` عربي RTL (`display: standalone`, `dir: rtl`, `lang: ar`).
- مسار `/robots.txt` يسمح بفهرسة الصفحات ويحجب `/api/`.

### د) ترويسات الأمان (`next.config.ts`)
يضيف التطبيق ترويسات الأمان القياسية على جميع المسارات دون كسر العرض داخل `iframe`:
- `Content-Security-Policy` ذاتية المصدر بالكامل — النصوص والصوت تصل عبر الوكيل الداخلي `/api` ووسائط المستخدم تُعرض كـ `blob:`/`data:`، فلا يُسمح بأي مصدر خارجي (لا خطوط ولا سكربتات ولا صور خارجية). **تضييق مستويين**: الإنتاج يُصدر `script-src 'self' 'unsafe-inline'` بلا `'unsafe-eval'` إطلاقاً (تُزال تلقائياً)، بينما التطوير يضيفها لأن أدوات Next.js DevTools تتطلبها
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`
- `X-Frame-Options: SAMEORIGIN`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), geolocation=()`

### هـ) حدود الثقة في مسارات التصدير (`/api/studio/export*`)
- سقوف صارمة لكل رفع: ١٢ ميغابايت للشريحة الواحدة، ٨٠ ميغابايت للصوت المخصص، ٥١٢ ميغابايت للطلب الكامل، ١٦ ميغابايت لجزء فيديو الخلفية — مع رفض `413` عند التجاوز
- تحقق البايتات السحرية (`isValidUploadedMediaHeader` / `isValidVideoBinaryHeader`) قبل أي كتابة على القرص: PNG/JPEG للشرائح، MP3/WAV للصوت، MP4/WebM لفيديو الخلفية — فلا يمكن تمرير ملف مسمّى زوراً إلى FFmpeg (رفض `415`)
- استدعاء FFmpeg عبر `execFile` بمصفوفة معاملات حصراً (لا واجهة shell) وكل القيم الرقمية مقيدة بالنطاقات قبل البناء
- لا سطح SSRF: كل روابط الخادم تُبنى من قوائم القراء الثابتة أو ثابت `QUL_API_BASE`

### و) التبعيات (`npm audit` نظيف)
صفر ثغرات في كامل الرسم البياني للتبعيات بعد إزالة تبعيات غير مستخدمة (`firebase-tools` كانت مصدر ثغرتين) وتثبيت رقع `postcss`/`postcss-selector-parser` عبر `overrides`.

### ز) التكامل المستمر وفحص القرّاء (جديد)
- **`/.github/workflows/ci.yml`**: خط CI واحد على كل push/PR إلى `main` — يثبّت، ثم فحص سقف الأسطر (`scripts/check-file-size.ts`، لا ملف يتجاوز ٦٠٠ سطراً)، ثم `eslint` ثم اختبارات الوحدة (`tsx --test`) ثم بناء الإنتاج ثم `npm audit --audit-level=high`؛ أي فشل يمنع الدمج ويمنع أي تراجع في الجودة
- **مهمة دورية أسبوعية** (cron الاثنين 06:00 UTC) تشغّل `scripts/check-reciters.ts`: طلب `HEAD` واحد لكل قارئ من الـ ٣٨ على شبكات CDN يرصد تعطل مجلدات EveryAyah أو تغير معدلات البت مبكراً (يكتب آخر تقرير في `scripts/.reciter-health.json` ويفشل الوظيفة عند أي قارئ مكسور)
- **الكاش الخادمي الدائم** (`lib/server-audio-cache.ts`): طبقة قرص ذاتية التنظيف في `/tmp/quran-audio-cache` بسقف ٢٥٦ ميغابايت/٤٠٩٦ ملفاً تُزيح الأقدم عند الامتلاء؛ الآية الكاملة (٢٠٠) تُخزّن خلف الطلب بلا حجب و`Range` يمرّر للمنبع ما لم تكن النسخة الكاملة مخزونة — الترويسة `X-Quran-Audio-Cache: hit/miss` تشخّص الحالة

## ٣. متغيرات البيئة والنشر (Environment & Deployment)

### متغيرات البيئة (`.env.example`)
- `GEMINI_API_KEY`: مفتاح سري على الخادم فقط (مُدرج لجاهزية قدرات الذكاء الاصطناعي المستقبلية على الخادم — لا يُسبق أبداً بـ `NEXT_PUBLIC_`).
- `APP_URL`: عنوان النشر الفعلي للتطبيق.

### البناء والنشر
- `next.config.ts` مضبوط بوضع `output: 'standalone'` للنشر السحابي الخفيف (Cloud Run / Docker) مع `typescript.ignoreBuildErrors: false`.
- يتطلب الخادم وجود `ffmpeg` و `ffprobe` في المسار (`PATH`) لتفعيل محركات تصدير الفيديو.
- يتم التحقق قبل أي إصدار عبر:
  1. `npx --yes tsx --test lib/*.test.ts` (٤٥/٤٥ ناجح)
  2. `npm run lint` (0 أخطاء، 0 تحذيرات)
  3. `npm run build` (بناء إنتاجي كامل بدون أخطاء)
  4. معاينة حية في متصفح حقيقي والتأكد من خلو Console من الأخطاء.
